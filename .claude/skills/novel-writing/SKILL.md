# 장편 소설 집필·퇴고

작품 하나는 저장소 루트의 `<작품명>/` 폴더 하나다. 단계는 아래 순서로 진행하고, 단계마다 사용자 확인을 받는다.

```
<작품명>/
├── README.md            # 표지, 로그라인, 목차 (발행용)
├── cover.png
├── intents.md           # 사용자 의도 3줄 (목적·문체·배경)
├── bible/               # 00_overview ~ 06_style_guide
└── chapters/
    ├── NN.md            # 완성된 장 (발행 대상)
    └── parts/NN_k.md    # 절 단위 초고
```

## ① 의도 받기
사용자에게 목적, 문체, 배경을 한 줄씩 받아 `intents.md`에 적는다(`templates/intents.md`). 모호하면 `deep-interview` 스킬로 정리한다. 장르 프리셋(`presets/`)을 고른다. 맞는 프리셋이 없으면 가장 가까운 것을 복사해 새로 만든다.

## ② 바이블 작성
`templates/bible/`의 7개 틀을 `<작품명>/bible/`로 복사해 채운다.
- `00_overview` 로그라인, 주제, 확정 사항, 열린 질문
- `01_world_timeline` 연표, 시대 분위기, 무대, 원작 정합 규칙(팬픽·후속작일 때)
- `02_characters` 인물, 말버릇, 결핍, 성장 곡선, **소지품 추적**, 장별 '확정된 사항'
- `03_power_system` 능력(무공·마법) 체계, 주인공 성장 단계, 결전 해법
- `04_factions` 세력, 핵심 물건의 행방
- `05_outline` 장별 회목, 무대, 시기, 핵심 전환, 절 구성, **장 끝 갈고리**
- `06_style_guide` 문체 규칙. 프리셋의 금지 어휘와 호칭을 가져온다. 예시는 `examples/wuxia_style_guide.md`

열린 질문은 추천안을 붙여 사용자에게 고르게 한다. 바이블이 확정되기 전에 본문을 쓰지 않는다.

## ③ 집필 (장 단위)
1. 절 단위로 `chapters/parts/NN_k.md`에 쓴다. 절이 끝날 때마다 `wc -m`으로 분량을 재고 다음 절로 간다.
2. 장을 다 쓰면 절들을 합쳐 `chapters/NN.md`를 만든다. 맨 위는 `# 제N장 回目 — 부제`, 절 머리는 `## 一`, `## 二` … 형식이다.
3. `scripts/check.sh <작품명>`으로 분량, 대사 비율, 금지어, 제목 형식을 검사하고 통과시킨다.
4. **바이블 갱신**: 그 장에서 새로 생긴 인물, 소지품 변화, 날짜, 복선을 `02_characters.md`의 `## N장에서 확정된 사항`에 적는다. 다음 장으로 넘길 지시("4장 시작 때 화살 회수 한 줄")도 여기에 적는다. 줄거리가 바뀌면 `05_outline.md`에 `*(N장 집필 결과로 수정)*`을 표시한다.
5. 다음 장을 쓰기 전에 앞 장의 마지막 절과 바이블의 '확정된 사항'을 다시 읽는다.

## ④ 퇴고 (N차)
**한 차수에 초점은 하나다.** 시작할 때 사용자에게 초점과 반영 방식을 묻는다(AskUserQuestion). 초점 후보:
- 문체 가이드 준수(대사 비율, 분량, 성장 문체, 말투)
- 연속성·설정 정합(연도, 나이, 소지품, 바이블과의 불일치). 바뀐 설정은 바이블에 `## 퇴고(날짜)에서 바뀐 정사 설정`으로 남긴다
- 문장 다듬기(반복, 상투구)
- 재미·긴장 구조(도입, 갈고리, 통쾌 장면, 늘어짐, 시한 압박)

먼저 `scripts/check.sh`로 진단 수치를 뽑아 질문에 함께 보여 준다.

### 운영
- 장마다 에이전트 하나를 붙인다(`general-purpose`). 지시문은 `prompts/revision_agent.md`를 채워 쓴다. 장별 사정(분량 초과, 시한이 걸린 장, 반전 장, 클라이맥스)은 '장별 특기 사항'에 넣는다.
- **한 번에 3~4장씩 묶어서 돌린다.** 10개를 동시에 돌리면 사용량 한도에 걸려 전부 멈춘다. 멈추면 `git diff --stat`으로 진행 상태를 확인하고 SendMessage로 이어 가게 한다.
- 에이전트 보고가 다른 장의 이음새를 바꾸면(예: "이 이야기는 다음 장에서 직접 전하겠다"), 아직 작업 중인 해당 장 에이전트에게 바로 알린다. 이 때문에 연달아 있는 장은 같은 묶음에 넣는 편이 낫다.
- 에이전트는 자기 파일만 고친다. 다른 장이나 바이블의 문제는 보고만 하게 한다.
- 에이전트가 '새로 넣은 설정'을 보고하면 사용자 확인 목록에 올린다.

### 마무리 검증 (메인 세션이 직접)
1. `scripts/check.sh <작품명>`으로 분량, 금지어, 형식을 다시 확인한다.
2. 에이전트들이 보고한 이음새 문제를 grep으로 하나씩 확인하고, 본문끼리 어긋나면 고친다. 날짜와 경과 기간은 앞뒤 장의 셈으로 맞춘다.
3. 바이블과 본문이 어긋나면 어느 쪽이 맞는지 판단해 보고한다. 바이블은 사용자 확인 뒤 고친다.
4. 장별 요약 표(글자 수, 주요 수정)와 확인이 필요한 목록을 보고한다.

## ⑤ 발행
- `README.md`: 표지 이미지, 로그라인, 목차(장 링크), 총 분량
- 완성본이 필요하면 `chapters/NN.md`를 순서대로 합친다. 완성본은 다시 만들 수 있으니 커밋하지 않아도 된다.
- 커밋 메시지: `feat: add <작품명> chapters 1-N`, `docs: <작품명> N차 퇴고 — <초점>`. git 작성자가 설정되어 있지 않으면 직전 커밋의 작성자를 `git -c user.name=… -c user.email=…`로 지정한다. 설정 파일은 바꾸지 않는다.
- push는 사용자가 요청할 때만 한다.
- `.ipynb_checkpoints/`, `.megamemory/`, `.memsearch/`는 커밋하지 않는다.

## 원칙
- 퇴고에서 줄거리, 인물 관계, 결말은 바꾸지 않는다. 개요에는 있는데 본문에 빠진 회수 장면은 채운다.
- 장 사이 연결(갈고리 → 다음 장 첫머리)은 늘 양쪽을 함께 읽고 판단한다.
- 고칠 필요가 없는 곳은 건드리지 않는다. 각 수정은 "무엇이 나아지는가"로 설명할 수 있어야 한다.
